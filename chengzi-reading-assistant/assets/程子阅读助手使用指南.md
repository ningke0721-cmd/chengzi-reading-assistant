# 程子阅读助手使用指南

> 从问题或兴趣出发，把阅读划线变成可追溯的知识、当前业务行动和复盘经验。

## 第一次使用：让 Codex 自动配置

第一次调用程子阅读助手时，Codex 会先检查：

- Obsidian 是否已经安装并能打开；
- 当前是否已有可复用的 Obsidian Vault；
- `Wechat Reading` 社区插件是否安装并启用；
- 微信读书同步目录是否正确；
- 阅读助手目录、配置文件和本指南是否齐全；
- 是否能够完成一次手动同步。

只读检查不会修改电脑。发现缺失项目后，Codex 会一次说明准备安装的软件、下载来源、目标位置、需要创建的目录和所需权限。你确认授权后，Codex 会继续完成所有能够自动完成的安装、配置和验证，不需要你照着长篇教程逐项操作。

你只需要亲自处理两类受保护信息：

1. 系统安装提示中的电脑密码；
2. 微信登录、验证码或微信读书 API Key。

请直接在系统、微信读书或 Obsidian 插件界面中输入这些信息，不要把密码或 API Key 发到聊天中。Codex 不会读取、保存或复制它们。

默认配置使用：

```text
微信读书同步目录：20-阅读资料/微信读书原始划线
阅读结论目录：20-阅读资料/阅读结论
```

配置完成后，Codex 会执行一次手动同步并检查 Markdown 文件是否正常生成。全部验证通过后，才会显示“程子阅读助手已经就绪”。

## 一分钟上手

在 Codex 中打开你的 Obsidian Vault，然后说：

> 我要读书

选择一种方式：

- **A 带着问题读书**：你有一个真实问题，希望找到合适的书和章节。
- **B 基于兴趣探索**：暂时没有明确问题，想从一本书或一个主题开始。
- **C 整理已有阅读**：已经读过并划线，希望整理到知识库。

你日常只需做三件事：

1. 阅读并划线，重要处写下自己的想法。
2. 把划线同步到 Obsidian。
3. 回到 Codex 说“《书名》第X章划线已经同步”。

没有 Obsidian 或微信读书插件时，也可以在普通 Markdown 工作区使用：把划线或章节内容导入为 Markdown，再告诉助手文件位置。联网和微信读书能力不是必需条件；无法核对书籍版本或目录时，助手会请你提供相应页面，不会凭记忆补全。

## A 带着问题读书

说：

> 我要读书，我最近的问题是……

助手会给一张简短诊断卡，帮助你澄清问题，然后：

- 判断你指定的书是否合适，或推荐最多3本书；
- 给出具体章节和每章要寻找的答案；
- 提供一个可靠短片段或明确标注的非原文内容预览；
- 把正式问题和下一步写入 Obsidian。

## B 基于兴趣探索

说：

> 我正在读《书名》，暂时没有明确问题。

助手不会要求你编造问题。章节整理后，内容会被分流为：

- 可以长期复用的通用知识；
- 可以用于当前业务的实践想法；
- 阅读中意外发现的新问题线索。

新问题先留在阅读结论中，准备行动时才正式创建。

## C 整理已有阅读

说：

> 《书名》第X章划线已经同步，请整理。

如果只读了一部分，助手只做阶段性读书笔记；如果整章完成，会继续进行知识分流。

## 章节完成后会发生什么

助手会判断四种去向：

1. **回答当前问题**：更新问题与行动。
2. **长期复用**：只有出现“新名词/概念 + 可解释案例”或“方法 + 可解释案例”时，才提出通用知识卡片；没有达到条件就不生成。
3. **当前业务应用**：更新或建议实践案例。
4. **新问题线索**：先保留在阅读结论中。

通用知识卡片不会直接写入，也不会按固定数量硬凑。助手先展示名称、分类、触发类型、原文依据、解释、步骤、案例和使用边界；你确认后才保存。

## 从知识到行动

实践案例只保留：

1. 要解决的问题；
2. 书中的方法；
3. 在当前业务中具体怎么做；
4. 执行反馈和复盘反馈。

执行中可以说：

> 更新执行反馈：我已经……

完成后可以说：

> 我来复盘了，结果是……

助手会根据真实证据把知识标记为“待验证”“已验证”或“已否定”。

## 常用指令

```text
我要读书
我要读书，我最近的问题是……
我正在读《书名》，暂时没有明确问题
《书名》第X章划线已经同步
这一章读完了，请整理
确认第1张知识卡片
更新执行反馈：……
我来复盘了：……
启动这个问题线索：……
程子阅读助手怎么用？
```

## 内容放在哪里

```text
10-问题与行动       正在解决的真实问题
20-阅读资料         原始划线与阅读结论
30-知识卡片
  通用工作知识      可跨业务复用的方法
  实践案例          当前业务的具体落地
40-复盘             执行结果与经验修正
```

## 使用原则

- 不需要先把问题想得特别清楚。
- 不需要为兴趣阅读强行寻找问题。
- 不要为了收藏或凑数量创建卡片，只保留有来源、可解释案例、可能复用的知识。
- 作者原文、你的想法和助手归纳会明确区分。
- 新问题不是立即增加任务，而是先作为线索保存。
- 每次只推进当前一步，避免知识库和行动方案过度复杂。
