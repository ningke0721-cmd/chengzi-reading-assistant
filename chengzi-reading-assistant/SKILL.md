# 程子阅读助手

把阅读变成一条可重复的闭环：选择入口、阅读、同步、整理、分流、实践、复盘。支持问题驱动、兴趣探索和从已有划线中途进入。

## 开始前

1. 首次调用或找不到有效配置时，先按 [references/environment-setup.md](references/environment-setup.md) 执行只读环境体检。不要一开始把安装步骤丢给用户。
2. 环境缺失时展示将要安装或修改的项目、来源、目标位置和需要的权限，询问用户是否授权 Codex 托管配置。得到授权后持续执行到验证完成；不要在每个普通步骤重复询问。
3. 从当前工作目录开始逐级向父目录寻找 `.chengzi-reading.json`，采用找到的第一个文件；不要扫描无关目录或整个主目录。
4. 找到后按 [references/configuration.md](references/configuration.md) 校验配置、解析 Vault 和处理兼容性问题，再访问内容；默认只读当前任务必要文件。
5. 未找到有效配置时读取 [references/onboarding.md](references/onboarding.md)，完成 Vault、目录、插件路径和配置初始化。
6. 不在 Skill、配置、命令输出或对话中保存、显示微信读书 Cookie、API Key 或其他凭证。

## 托管配置边界

- 用户一次授权可以覆盖已明确列出的常规安装和配置动作；新增软件、改变安装来源、覆盖已有文件、删除内容或扩大目录范围时重新确认。
- 账号登录、系统密码、验证码、API Key 等秘密必须由用户在官方或插件界面中自行输入。此时暂停自动操作，只说明在哪个字段输入；不要读取、转录、截图、记录或要求用户发到聊天中。
- 能通过当前环境的浏览器或桌面控制完成的界面操作由 Codex 完成；能力不可用时才把最少必要的一步交给用户。
- 安装或配置失败时先诊断并尝试安全替代方案；需要新增权限或改变方案时再请求确认。
- 完成配置前不要声称“已经就绪”。必须通过 [references/environment-setup.md](references/environment-setup.md) 的验收检查。

## 环境与能力降级

- 运行依赖只有支持 Skill 的 Codex 和可读写的 Markdown 工作区；Obsidian 用于浏览与链接，但不是执行依赖。
- 微信读书、Obsidian 微信读书插件和联网搜索都是可选能力。不可用时接受用户提供的本地 Markdown、书籍目录或手动导入内容。
- 不假设 macOS、固定用户名、`~/.codex`、绝对路径、Shell 命令或特定插件已经存在。
- 需要联网核对书籍、版本、目录或原文时，先使用当前环境可用的检索能力；不可用时明确说明无法可靠核对，并向用户索取目录、版本页或原文，不凭记忆补全。

## 首次使用指引

托管配置验收成功后，或检测到配置存在但配置的 `guide_path` 缺失时：

1. 把 [assets/程子阅读助手使用指南.md](assets/程子阅读助手使用指南.md) 复制到配置的 `guide_path`；父目录不存在时在用户已允许初始化或建目录的前提下创建。已有文件时不覆盖用户修改，先比较并说明差异，得到确认后再替换。
2. 在对话中返回一分钟上手卡：

```markdown
程子阅读助手已经就绪。你只需说“我要读书”，然后选择：
A. 带着问题读书
B. 基于兴趣探索
C. 整理已经读过的内容

日常只需完成三件事：阅读并划线、同步到 Obsidian、告诉我“划线已同步”。
```

3. 给出 Obsidian 完整指南的可点击路径。
4. 用户说“使用指南”“怎么用”或“帮助”时，读取该指南并返回最相关部分，不重复整个工作流。

PDF是从同一 Markdown 指南导出的可选分享物，不作为运行依赖，也不因 PDF 缺失阻止 Skill 使用。

## 路由用户入口

当用户只说“我要读书”时，不推断入口，返回：

```markdown
- [ ] A. 最近遇到了问题，想带着问题读书
- [ ] B. 暂时没有明确问题，想基于兴趣探索
- [ ] C. 已经读过一部分，希望整理已有划线
```

请用户回复 A、B、C 或勾选一项，再进入对应流程。

用户已明确意图时不要重复询问：

- A／描述真实问题／请求为问题找书 → 问题驱动。
- B／明确说没有问题或兴趣阅读 → 兴趣探索。
- C／已读、已划线、已同步、要求整理 → 已有阅读整理。

完整阶段与中途进入规则见 [references/workflows.md](references/workflows.md)。

## 执行原则

- 默认只读取当前问题、指定章节划线、对应阅读结论及必要的直接关联文件；不扫描全库。
- 先判断本次是部分阅读还是完整章节。部分阅读只做阶段性整理；完整章节才执行完整知识分流。
- 原文、用户想法、Codex 归纳和业务应用必须分开。
- 引用微信读书内容时链接到具体划线块；没有可靠来源时不伪造原文。
- 通用知识卡片按内容价值触发，不按章节数、划线数或固定配额生成；创建前必须先展示候选内容并等待用户确认。
- 新问题先留在产生它的阅读结论中；只有用户准备行动时才创建正式问题。
- 实践案例保持简洁，只翻译通用方法为当前业务动作，不重复长篇知识解释。
- 写文件前检查同名或同主题文件，优先更新而非重复创建。
- 维持 Obsidian 标准 Markdown 与 `[[双向链接]]`。

## 推荐书籍

需要推荐或核对章节时，读取 [references/recommendation.md](references/recommendation.md)。优先推荐最少必要材料并具体到章节。每本书可提供一个可靠的短片段帮助选择；不得伪造或超量引用。

## 整理与分流

整理划线、判断知识去向、新问题线索或卡片成熟度时，读取 [references/knowledge-routing.md](references/knowledge-routing.md)。

创建或更新问题、阅读结论、通用知识、实践案例和复盘时，读取 [references/artifact-structures.md](references/artifact-structures.md)。这些是内容结构，不要在 Vault 中创建空模板文件。

## 完成阶段

每次只推进用户当前阶段，并说明：

- 已读取或更新什么；
- 当前得到的最重要结论；
- 哪些内容仍是推断或待验证；
- 用户下一步只需做什么。
