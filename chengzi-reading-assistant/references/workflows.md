# 工作流

## A. 问题驱动阅读

### 诊断卡

```markdown
1. 我想解决的问题：
2. 一个最典型的真实例子：
3. 我主要卡在：不知道原因／不知道怎么做／执行不了／做过但效果不好／其他
4. 我希望阅读后能够做到：
5. 是否有想读的书：有，书名／没有，请推荐
```

用户填写后：

1. 区分现象、直接行为和待验证根因。
2. 把问题改写成可行动、可判断是否改善的表达。
3. 判断指定书是否合适；需要推荐时按 recommendation.md 执行。
4. 推荐最少必要章节和每章要寻找的答案。
5. 创建或更新问题与行动，并更新首页当前任务。

## B. 兴趣探索阅读

只确认：兴趣主题、是否已有书、希望建立认识／深入主题／寻找工作启发／边读边发现。

不强迫建立问题。阅读结论使用：

```yaml
reading_mode: exploratory
related_problem: []
```

后续发现实际问题时改为 `mixed` 并增加问题链接，不移动阅读结论。

## C. 已有阅读整理

确认书名、章节、划线是否同步，以及用户希望阶段整理、完整章节、知识卡片或自动判断。读取本地原始划线，判断部分／完整章节后继续。

## 划线已同步

1. 只查找相关书和章节。
2. 读取已有问题与阅读结论，避免重复。
3. 部分阅读：更新阶段性阅读结论和下一步，不完整分流。
4. 完整章节：更新阅读结论，并按 knowledge-routing.md 四路分流。

## 用户确认卡片

只创建用户确认的卡片。允许用户修改名称、分类、解释和案例。创建后将其链接回阅读结论、问题和实践案例。

## 执行反馈

用户口述实际执行后，将其整理进对应实践案例的“执行反馈”。记录事实、偏差和计划外情况；不根据单次结果擅自宣布方法有效。

## 复盘反馈

整理实际动作、结果、原因判断、有效与无效部分、下一步。写入 `40-复盘/`，回链问题、实践案例和通用知识。根据证据把案例标为 `有效`、`部分有效` 或 `无效`，把知识标为 `待验证`、`已验证` 或 `已否定`。

## 启动问题线索

从产生线索的阅读结论读取来源与上下文，创建正式问题到 `10-问题与行动/`，将线索状态改为 `已启动` 并链接新文件。完成行动和复盘后改为 `已解决`。
