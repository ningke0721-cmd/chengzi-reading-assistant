# 知识分流与溯源

## 部分阅读

只整理已读范围：一句话收获、作者观点、原文链接、用户想法、Codex 阶段归纳、对当前问题的帮助和下一步。明确 `status: partial`，不把它写成全章结论。

## 完整章节的四路分流

在阅读结论增加 `本章知识去向`：

1. `回答当前问题`：更新已有问题与相关实践案例。
2. `可以长期复用`：按内容价值提议通用知识卡片；不设固定数量，可以是 0 张，也不要为凑数量生成。
3. `当前业务应用`：更新已有实践案例；准备执行独立行动时才新建案例。
4. `意外发现的新问题`：先留在阅读结论。

## 新问题线索

记录问题名称、触发章节或划线、价值、与当前问题关系、状态和启动条件。状态仅用：

- `问题线索`
- `已启动`
- `已解决`

不要建立独立问题池。没有近期行动意图时不创建正式问题。

## 候选通用知识

只在内容通过“知识单元 + 可解释案例”双门槛时提议卡片：

- `新名词/概念 + 可解释案例`：出现一个对用户当前知识库有新增解释价值的名词或概念，并且有具体案例能说明它如何发挥作用。
- `方法/流程 + 可解释案例`：出现一套可迁移的方法、步骤、流程或判断标准，并且有具体案例能说明它如何使用。

案例可以来自作者原文、书中叙事、用户提供的真实业务情境，或本次阅读中有来源支撑的应用场景；必须可追溯，不能为了生成卡片自行编造。

不要把以下内容提议为通用知识卡片：

- 只有金句、观点或章节摘要，没有新名词、概念或方法。
- 只有抽象概念或方法，没有案例解释。
- 只有案例故事，没有可抽象复用的概念或方法。
- 已有卡片能覆盖，且本次阅读没有新增解释、边界或案例。
- 只是回答当前问题的一次性结论，不能跨场景复用。

写入前展示：名称、工作问题分类、触发类型（`概念+案例` 或 `方法+案例`）、核心观点、名词解释或方法步骤、可追溯案例、原文依据、提炼过程、当前问题应用、使用边界和 `待验证` 状态。等待用户确认。若没有候选，明确说明“本章没有达到知识卡片触发条件的内容”，只更新阅读结论或实践案例。

## 溯源规则

- 至少一个可追溯来源。
- 作者原文、用户想法、Codex 归纳、业务应用分开。
- 原文优先使用 `[[原始笔记#^block-id|说明]]` 链接。
- 没有直接支持的内容标为归纳、推断或应用建议。
- 书中没有案例、步骤或结论时不自行编造。

## 阅读模式

- `problem-driven`：关联正式问题。
- `exploratory`：没有预设问题。
- `mixed`：兴趣与问题并存或中途转化。

三种模式使用同一目录，以属性和链接区分，不建立第二套知识库。
